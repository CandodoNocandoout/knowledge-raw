# 金融知识地图

## 1. 文档定位

本文是金融知识库的「知识地图」。

本文回答三个问题：

1. 金融知识库包含哪些主要知识领域？
2. 每个知识领域负责回答什么问题？
3. 不同知识领域之间存在什么基本关联？

本文主要用于：

- LLM理解金融知识库整体结构
- RAG确定知识检索方向
- 后续问题路由
- 后续知识关系建立
- 多知识模块组合分析

本文不是具体金融知识的主要来源。

当需要回答具体金融概念、指标定义、计算方法或分析规则时，应优先检索对应的具体知识文件。

# 3. 宏观经济

## 3.1 knowledge_id

```text
MACRO
```

## 3.2 知识领域

宏观经济。

## 3.3 核心问题

宏观经济知识主要回答：

> 当前整体经济环境是什么？

包括：

* 经济增长
* 通胀
* 经济周期
* 企业经营环境
* 宏观环境变化

## 3.4 分析对象

宏观经济主要分析：

```text
经济增长
通胀
经济周期
企业经营环境
```

## 3.5 关联知识

宏观经济与以下知识存在关联：

```text
MACRO → RATE
关系：宏观经济环境影响利率环境

MACRO → MONETARY
关系：宏观经济环境影响货币政策背景

MACRO → PE
关系：宏观环境可能影响盈利预期和估值环境

MACRO → PB
关系：宏观环境可能影响企业盈利能力和资产定价
```

## 3.6 知识边界

宏观经济不能单独用于判断：

* 某只股票一定上涨
* 某只股票一定下跌
* 某家公司一定值得投资

宏观经济主要提供：

> 市场和企业分析的背景环境。

# 4. 利率

## 4.1 knowledge_id

```text
RATE
```

## 4.2 知识领域

利率。

## 4.3 核心问题

利率知识主要回答：

> 资金价格如何变化，以及利率变化可能如何影响经济、企业和资产估值。

## 4.4 关联知识

```text
RATE → MONETARY
关系：货币政策通常会影响利率环境

RATE → PE
关系：利率环境与估值水平存在关联

RATE → PB
关系：利率环境可能影响资产定价和估值水平

RATE → MACRO
关系：利率是宏观经济环境的重要变量
```

## 4.5 知识边界

利率下降不能直接推导：

> 股票一定上涨。

利率变化需要结合：

* 盈利预期
* 风险偏好
* 流动性
* 市场定价

共同分析。

# 6. ROE

## 6.1 knowledge_id

```text
ROE
```

## 6.2 知识领域

企业盈利能力与资本回报分析。

## 6.3 核心问题

ROE主要回答：

> 企业使用股东资本创造利润的能力如何？

## 6.4 关联知识

```text
ROE → PB
关系：ROE是分析PB的重要参考变量

ROE → PE
关系：盈利能力会影响市场对企业盈利的定价

ROE → CASHFLOW
关系：现金流可以辅助判断ROE对应利润的质量和可持续性
```

## 6.5 重要判断规则

不能建立以下简单关系：

```text
ROE高 → 企业一定优秀
```

正确关系是：

> ROE是企业资本回报能力的重要指标，但需要结合持续性、杠杆、利润率、资产周转和现金流等因素分析。

## 7.3 核心问题

现金流分析主要回答：

```text

关系：现金流质量可能影响对盈利估值的理解

CASHFLOW → PB
关系：现金流可以辅助分析企业资产和盈利质量
```

## 7.5 重要判断规则

不能建立：

```text

```

> 现金流与利润出现明显背离时，需要进一步分析其原因、持续时间和业务背景。

# 12. 核心知识关系

以下关系是当前金融知识库中最重要的跨知识关系。

## 12.1 ROE与PB

```text
source: ROE
target: PB
relation: 估值解释
```

说明：

> ROE反映企业资本回报能力，PB反映市场相对于净资产的定价水平。分析PB时应考虑ROE，但ROE不能单独决定PB。

---

## 12.2 ROE与现金流

```text
source: ROE

```

说明：

> ROE反映资本回报能力，现金流可以帮助判断利润的兑现程度和质量。

---

## 12.3 PE与ROE

```text
source: PE
target: ROE

```

说明：

> PE描述市场对盈利的定价，ROE描述资本回报能力，两者可以结合分析企业盈利能力与估值之间的关系。

---

## 12.4 PE与利率

source: PE
target: RATE

```

说明：

## 12.5 趋势与量价

# 14. 知识使用原则

## 原则1：单指标不能直接形成结论

例如：

```text
PE低
```

只能说明：

> 当前价格相对于当前盈利的倍数较低。

不能直接说明：

> 股票便宜。

---

## 原则2：不同知识模块回答不同问题

```text
MACRO
回答：环境如何？

ROE
回答：企业资本回报如何？

CASHFLOW
回答：利润是否形成现金？

PE
回答：市场给盈利多少估值？

PB
回答：市场给净资产多少估值？

TREND
回答：价格结构如何？

VOLUME_PRICE
回答：价格变化是否得到成交量支持？
```

---

## 原则3：关联不是因果

当知识地图写：

```text
ROE → PB
```

其含义是：

> ROE与PB存在分析关联。

不是：

> ROE变化必然导致PB变化。

同理：

```text
RATE → PE
```

表示：

> 利率与PE存在估值分析关联。

不是：

> 利率下降必然导致PE上涨。

# 15. 知识地图的LLM解释规范

当LLM读取本文时，应遵循：

```text
1. knowledge_id代表一个独立知识领域。

2. relation代表知识之间的分析关联。

3. relation不是自动因果关系。

4. source → target表示分析方向，不表示机械因果。

5. 具体问题应优先检索对应的具体知识文件。

6. 多知识问题可以组合多个knowledge_id。

7. 不得仅依据知识地图中的关联关系生成具体金融结论。

8. 当具体知识文件与本地图描述不一致时，以具体知识文件为准。
```

# 16. 金融知识库最小知识模型

金融知识库可以抽象成以下结构：

```text
知识领域
+
核心问题
+
分析对象
+
关联知识
+
关系类型
+
知识边界
+
使用条件
+
禁止的机械推理
```

其中：

> **知识边界和禁止的机械推理，与知识本身同样重要。**

因为金融分析中最常见的错误不是“不知道指标”，而是：

> 把一个指标直接当成结论。

# 18. 核心原则

整个金融知识库遵循：

> **宏观描述环境，财务描述企业，估值描述价格，技术描述市场行为。**

进一步：

> **单一指标描述现象，多指标组合用于解释，跨模块关系用于建立分析框架，但任何关系都不能在缺乏具体证据时直接转化为因果结论。**

```
