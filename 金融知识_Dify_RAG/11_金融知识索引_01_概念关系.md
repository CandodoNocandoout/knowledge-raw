# 金融知识概念关系

## 1. 文档定位

本文用于定义金融知识库中不同知识概念之间的关系。

本文重点回答：

> “A 和 B 为什么需要放在一起分析？”

本文不负责：

- 详细解释单个金融概念
- 给出具体公司的投资结论
- 预测股票价格
- 替代具体金融知识文件

当需要理解某个概念的详细定义、公式、计算方法和具体判断规则时，应优先检索对应的金融知识文件。

---

# 2. 关系模型

本知识库使用以下关系模型描述金融概念之间的关联：

```text
source
target
relation
direction
meaning
usage
caution
```

含义如下：

| 字段        | 含义          |
| --------- | ----------- |
| source    | 起始概念        |
| target    | 关联概念        |
| relation  | 两个概念之间的关系类型 |
| direction | 分析方向        |
| meaning   | 关系具体含义      |
| usage     | 什么时候使用这个关系  |
| caution   | 使用时需要避免的错误  |

重要规则：

> `source → target` 表示分析关联方向，不自动表示因果关系。

例如：

```text
ROE → PB
```

表示：

> 分析PB时可以参考ROE。

不表示：

> ROE变化必然导致PB变化。

---

# 3. 关系类型

当前知识库主要使用以下关系类型。

## 3.1 定义关系

用于表示：

> 一个概念用于解释另一个概念的组成或含义。

示例：

```text
ROE → 资本回报能力
```

---

## 3.2 估值关联

用于表示：

> 某个企业指标可以帮助解释某个估值指标。

例如：

```text
ROE → PB
ROE → PE
```

---

## 3.3 盈利质量验证

用于表示：

> 某个指标可以用于验证企业盈利质量。

例如：

```text
CASHFLOW → ROE
CASHFLOW → PE
```

---

## 3.4 环境关联

用于表示：

> 宏观环境变量与企业或市场指标存在分析关联。

例如：

```text
RATE → PE
MACRO → PE
MONETARY → RATE
```

---

## 3.5 市场行为验证

用于表示：

> 某个市场行为指标可以辅助验证另一个市场行为指标。

例如：

```text
VOLUME_PRICE → TREND
```

---

## 3.6 分析组合关系

用于表示：

> 两个概念通常需要组合使用，但不存在明确的因果方向。

例如：

```text
PE ↔ PB
ROE ↔ CASHFLOW
TREND ↔ VOLUME_PRICE
```

# 4. ROE与PB

## Relation ID

```text
REL-ROE-PB
```

## Source

```text
ROE
```

## Target

```text
PB
```

## Relation

```text
估值关联
```

## Direction

```text
ROE → PB
```

## Meaning

ROE反映企业使用股东资本创造利润的能力。

PB反映市场价格相对于企业账面净资产的水平。

因此，在分析PB是否具有合理性时，可以参考企业ROE。

一般而言：

> 企业资本回报能力是理解市场如何给净资产定价的重要因素之一。

## Usage

当用户提出以下问题时，可以组合ROE和PB：

* PB低是不是便宜？
* PB高是不是贵？
* 为什么两家公司PB差异很大？
* 同行业公司PB为什么不同？
* 高ROE企业为什么可能拥有更高PB？

## Caution

不能建立：

```text
ROE高 → PB一定高
```

也不能建立：

```text
ROE低 → PB一定低
```

PB还受到：

* 盈利预期
* 资产质量
* 行业特征
* 风险
* 利率
* 市场情绪

等因素影响。

# 6. ROE与现金流

## Relation ID

```text
REL-ROE-CASHFLOW
```

## Source

```text
ROE
```

## Target

```text
CASHFLOW
```

## Relation

```text
盈利质量验证
```

## Direction

```text
ROE → CASHFLOW
```

## Meaning

ROE反映企业资本回报能力。

现金流可以帮助进一步判断：

> 企业账面利润是否能够形成相应的现金流。

因此，ROE分析不能完全脱离现金流。

## Usage

当用户提出：

* ROE很高是否代表企业很好？
* ROE持续上升意味着什么？
* 企业盈利能力是否真实？
* 利润增长是否具有质量？

可以组合：

```text
ROE
+
CASHFLOW
```

## Caution

不能建立：

```text
现金流下降 → ROE一定失真
```

现金流变化可能受到：

* 应收账款
* 存货
* 预付款
* 经营周期
* 季节性
* 行业周期

等因素影响。

# 7. 现金流与ROE

## Relation ID

```text
REL-CASHFLOW-ROE
```

## Source

```text
CASHFLOW
```

## Target

```text
ROE
```

## Relation

```text
盈利质量验证
```

## Direction

```text
CASHFLOW → ROE
```

## Meaning

当现金流出现明显变化时，可以进一步观察ROE以及净利润变化。

这样可以判断：

> 企业盈利能力变化是否伴随着现金创造能力变化。

## Usage

例如：

```text
净利润 ↑
ROE ↑
经营现金流 ↓
```

此时应该进一步调查利润与现金流之间的背离原因。

## Caution

现金流与ROE不一致并不自动代表财务异常。

必须结合具体业务和会计项目分析。

PE还受到：

* 盈利增长
* 盈利稳定性
* 利率
* 风险
* 行业特征
* 市场预期

影响。

```

```

```text

```

PE使用企业盈利作为估值基础。

现金流可以帮助判断：

> 当前盈利是否具有较好的现金兑现能力。

现金流弱于净利润不自动意味着PE失效。

需要分析产生差异的具体原因。

```text

```

```text

```

```text

```

## Relation

```text

→

→

```

## Meaning

这是一个分析框架，而不是严格因果链。

三个层面分别回答：

```text
基本面：
企业本身怎么样？

估值：
市场给企业什么价格？

技术：
市场目前如何交易？
```

因此，当用户提出复杂股票问题时，可以分别从三个层面分析。

## Caution

三个层面的结论可能互相矛盾。

例如：

```text
企业质量良好
+
估值较高
+
技术趋势走弱
```

这不是知识冲突。

而是：

> 不同分析维度描述了不同事实。

LLM不应强行把三个维度统一成一个结论。

# 29. LLM关系解释规范

LLM读取本文时，应遵循以下规则：

1. `source → target`表示分析关联，不自动表示因果关系。
2. `↔`表示两个概念适合组合分析。
3. `relation`描述为什么需要组合两个概念。
4. `usage`描述什么情况下应该调用该关系。
5. `caution`描述该关系容易产生的错误推理。
6. 不得仅根据关系本身生成投资结论。
7. 具体金融事实必须优先来自具体知识文件。
8. 当多个知识模块发生冲突时，不应强行消除冲突。
9. 不同指标描述不同维度，指标之间可以互补，也可以出现背离。
10. 发现背离时，应将其作为进一步分析的入口，而不是直接作为结论。

# 31. 核心思想

金融知识之间不是简单的：

```text
A → B → C
```

而更接近：

```text
概念
+
关联概念
+
环境变量
+
交叉验证
+
知识边界
```

因此，本知识库采用：

> **“概念 + 关系 + 使用场景 + 边界”**

而不是：

> **“指标 + 单一结论”**

作为LLM进行金融分析时的基础知识结构。
