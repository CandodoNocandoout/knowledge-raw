金融知识概念关系

<<<DIFY_PARENT>>>

1. 文档定位

本文用于定义金融知识库中不同知识概念之间的关系。

本文重点回答：

“A 和 B 为什么需要放在一起分析？”

本文不负责：

详细解释单个金融概念给出具体公司的投资结论预测股票价格替代具体金融知识文件

当需要理解某个概念的详细定义、公式、计算方法和具体判断规则时，应优先检索对应的金融知识文件。

<<<DIFY_PARENT>>>

2. 关系模型

本知识库使用以下关系模型描述金融概念之间的关联：

source
target
relation
direction
meaning
usage
caution

含义如下：

| 字段 | 含义 |
| --------- | ----------- |
| source | 起始概念 |
| target | 关联概念 |
| relation | 两个概念之间的关系类型 |
| direction | 分析方向 |
| meaning | 关系具体含义 |
| usage | 什么时候使用这个关系 |
| caution | 使用时需要避免的错误 |

重要规则：

source → target 表示分析关联方向，不自动表示因果关系。

例如：

ROE → PB

表示：

分析PB时可以参考ROE。

不表示：

ROE变化必然导致PB变化。

3. 关系类型

当前知识库主要使用以下关系类型。

<<<DIFY_CHILD>>>

3.1 定义关系

用于表示：

一个概念用于解释另一个概念的组成或含义。

示例：

ROE → 资本回报能力

<<<DIFY_CHILD>>>

3.2 估值关联

用于表示：

某个企业指标可以帮助解释某个估值指标。

例如：

ROE → PB
ROE → PE

<<<DIFY_CHILD>>>

3.3 盈利质量验证

用于表示：

某个指标可以用于验证企业盈利质量。

例如：

CASHFLOW → ROE
CASHFLOW → PE

<<<DIFY_CHILD>>>

3.4 环境关联

用于表示：

宏观环境变量与企业或市场指标存在分析关联。

例如：

RATE → PE
MACRO → PE
MONETARY → RATE

<<<DIFY_CHILD>>>

3.5 市场行为验证

用于表示：

某个市场行为指标可以辅助验证另一个市场行为指标。

例如：

VOLUME_PRICE → TREND

<<<DIFY_CHILD>>>

3.6 分析组合关系

用于表示：

两个概念通常需要组合使用，但不存在明确的因果方向。

例如：

PE ↔ PB
ROE ↔ CASHFLOW
TREND ↔ VOLUME_PRICE

4. ROE与PB

<<<DIFY_CHILD>>>

Relation ID

REL-ROE-PB

<<<DIFY_CHILD>>>

Source

ROE

<<<DIFY_CHILD>>>

Target

PB

<<<DIFY_CHILD>>>

Relation

估值关联

<<<DIFY_CHILD>>>

Direction

ROE → PB

<<<DIFY_CHILD>>>

Meaning

ROE反映企业使用股东资本创造利润的能力。

PB反映市场价格相对于企业账面净资产的水平。

因此，在分析PB是否具有合理性时，可以参考企业ROE。

一般而言：

企业资本回报能力是理解市场如何给净资产定价的重要因素之一。

<<<DIFY_CHILD>>>

Usage

当用户提出以下问题时，可以组合ROE和PB：

PB低是不是便宜？PB高是不是贵？为什么两家公司PB差异很大？同行业公司PB为什么不同？高ROE企业为什么可能拥有更高PB？

<<<DIFY_CHILD>>>

Caution

不能建立：

ROE高 → PB一定高

也不能建立：

ROE低 → PB一定低

PB还受到：

盈利预期资产质量行业特征风险利率市场情绪

等因素影响。

+

不能建立：

现金流变化可能受到：

等因素影响。

Meaning

估值：

这不是知识冲突。

不同分析维度描述了不同事实。

LLM不应强行把三个维度统一成一个结论。

28. 关系使用优先级

当用户提出复杂问题时，可以按照以下顺序组合知识：

第一优先级：

第二优先级：

第三优先级：

29. LLM关系解释规范

LLM读取本文时，应遵循以下规则：

source → target表示分析关联，不自动表示因果关系。↔表示两个概念适合组合分析。relation描述为什么需要组合两个概念。usage描述什么情况下应该调用该关系。caution描述该关系容易产生的错误推理。不得仅根据关系本身生成投资结论。具体金融事实必须优先来自具体知识文件。当多个知识模块发生冲突时，不应强行消除冲突。不同指标描述不同维度，指标之间可以互补，也可以出现背离。发现背离时，应将其作为进一步分析的入口，而不是直接作为结论。

31. 核心思想

金融知识之间不是简单的：

A → B → C

而更接近：

概念
+
关联概念
+
环境变量
+
交叉验证
+
知识边界

因此，本知识库采用：

“概念 + 关系 + 使用场景 + 边界”

而不是：

“指标 + 单一结论”

作为LLM进行金融分析时的基础知识结构。
